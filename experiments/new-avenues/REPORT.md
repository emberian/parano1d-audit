# Header availability and mining readiness — source review

**Status (2026-11-15):** No mined-header or wire-level test was completed. An automatic cybersecurity review blocked a related local test, so this lane stopped before executing its probe. A local, uncommitted Rust probe was written but its build was interrupted; it produced no observation. The mechanism below is inferred from pinned source, not demonstrated on mainnet or a devnet.

## A. A valid higher-work header can carry unverified object availability

**Consequence if reproduced:** A non-isolated miner may stop building proofs and searching nonces on its last committed tip while trying to obtain objects the announcing peer does not hold. This could affect availability and miner competition; it does not demonstrate coin theft or a selective-sale mechanism.

The required conditions are:

1. The announcing peer has a profile-verified, dispatchable P2P connection. Direct availability messages are accepted from such a peer when BODY and TERMINAL flags are present, at most 20 per 10 seconds; the P2P ingress labels the announcement `source_has_objects: true` without testing possession ([network.rs:7377–7395](../../parano1d/noid_p2p/src/network.rs#L7377)). The node treats this as exact inventory only while the peer remains in `manifest_peers` ([main.rs:10005–10016](../../parano1d/noid_node/src/main.rs#L10005)).
2. The header must pass native parent, height, ASERT, timestamp, PoW, and slot-depth checks ([header.rs:200–264](../../parano1d/noid_chain/src/consensus/header.rs#L200)). A direct child of the canonical tip wins over the tip by positive additional work; a competing selected branch may instead defeat it. Merely advertising a height or an invalid header is insufficient ([main.rs:10143–10239](../../parano1d/noid_node/src/main.rs#L10143)).
3. The body and terminal IDs need only match the header's claims, have a permitted proof class, and claim bounded nonzero lengths. Their digests and actual bytes are not attested by `HeaderInventoryRecord::validate` ([header_protocol.rs:224–245](../../parano1d/noid_p2p/src/header_protocol.rs#L224)). A syntactically valid but nonexistent pair can therefore construct a `SuffixOffer::live` for the selected direct child ([main.rs:10251–10268](../../parano1d/noid_node/src/main.rs#L10251)).

If admission succeeds, `main.rs` immediately sets `unresolved_better_header=true` and starts exact-object requests ([main.rs:10269–10304](../../parano1d/noid_node/src/main.rs#L10269)). The mining gate makes `proof_build_ready` false while unresolved, and nonce readiness depends on proof readiness ([mining_readiness.rs:214–224](../../parano1d/noid_node/src/networking/mining_readiness.rs#L214)). The ordinary P2P peer that lacks the objects appears to answer with missing payloads, which the suffix sync interprets as source unavailability; this behavior was not exercised here. Once transport is truly extinct, recovery also requires six discovery rounds, no pending probes, and at least 45 seconds since plan progress ([main.rs:14943–14965](../../parano1d/noid_node/src/main.rs#L14943)). This is a **source-derived lower bound on that retirement branch**, not a measured pause duration or guarantee that the branch fires.

The announcing miner expends real PoW for each new header and earns no block reward from a withheld body. It can obtain a reward only by later providing a complete accepted block. The opportunity cost and relative benefit depend on other miners' hashpower and the target interval (20 seconds before v2, 30 seconds at v2; [params.rs:6–18](../../parano1d/noid_chain/src/consensus/params.rs#L6)). A network that produces a stronger competing branch can supersede the stalled plan ([main.rs:5182–5218](../../parano1d/noid_node/src/main.rs#L5182)); the effect would matter most when the affected miner supplies a material fraction of effective mining power or has poor access to other miners.

## B. Repeated `Busy` replies may preserve the pause without a time ceiling

**Busy response variant, unverified at the wire level:** The exact-object protocol permits canonical `Busy` responses with retry intervals from 100 to 10,000 ms ([object_protocol.rs:20–42](../../parano1d/noid_p2p/src/object_protocol.rs#L20)); the decoder accepts a Busy response with no payload ([object_codec.rs:115–129](../../parano1d/noid_p2p/src/object_codec.rs#L115)). In the node, a Busy response calls `SuffixSync::request_busy` ([main.rs:10552–10575](../../parano1d/noid_node/src/main.rs#L10552)), which calls `ObjectFetcher::busy_source` ([suffix_sync.rs:662–686](../../parano1d/noid_node/src/networking/suffix_sync.rs#L662)). That function increases backoff but retains the source regardless of the Busy count ([object_fetcher.rs:564–608](../../parano1d/noid_node/src/networking/object_fetcher.rs#L564)). `unfinished_transport_is_extinct` is false while any source remains and explicitly excludes Busy from extinction ([object_fetcher.rs:859–879](../../parano1d/noid_node/src/networking/object_fetcher.rs#L859)). The 45-second retirement condition requires extinction ([main.rs:14943–14948](../../parano1d/noid_node/src/main.rs#L14943)).

If a connected provider keeps returning properly correlated Busy replies for unavailable exact IDs, the visible state machine has no Busy-count or no-progress ceiling that restores mining on the committed tip. This is a **conditional source-level liveness gap**, not proof of an indefinite network pause: a stronger competing branch, disconnection, malformed response, or another authenticated provider may end or replace the plan. The ordinary node P2P implementation returns Busy only when its serving lease is full ([network.rs:7182–7215](../../parano1d/noid_p2p/src/network.rs#L7182)); continued Busy replies under other conditions would require custom provider behavior.

## Limits and alternative paths

- Header-only gossip does not itself make an exact suffix plan; the node explicitly keeps mining on the committed view until object inventory is available ([main.rs:10203–10206](../../parano1d/noid_node/src/main.rs#L10203), [main.rs:10251–10254](../../parano1d/noid_node/src/main.rs#L10251)).
- `--genesis` sets the mining quorum to isolated mode ([main.rs:2323–2328](../../parano1d/noid_node/src/main.rs#L2323)); its readiness snapshot unconditionally returns ready ([mining_readiness.rs:183–191](../../parano1d/noid_node/src/networking/mining_readiness.rs#L183)). The saved `p8-n1` node was launched with `--genesis` ([phase8_live_c26.py:77–79](../devnet-chaos/scripts/phase8_live_c26.py#L77)), so it cannot test this proposed pause. The test requires a non-isolated miner. This creates a possible operational difference between miners using the bypass and ordinary miners, but the flag is available to anyone who runs a node; it is not operator-exclusive authority.
- The header cannot bypass PoW or future-drift validation, and unmatched object bytes cannot commit state. The concern is the pause before exact body and terminal verification, not acceptance of corrupted state.
- Other peers do not possess invented exact object IDs. They can help by producing a stronger branch, or by providing the actual objects if a complete block was published; merely connecting to other peers does not validate advertised availability.

## Follow-up measurements and possible changes

Ranked decisive checks, if authorized later:

1. A bounded, isolated **non-isolated miner** control from an already synchronized tip. Record `proof_ready`, `nonce_ready`, canonical height, exact-plan admission, and recovery against an otherwise identical no-announcement control. Use one natively valid header; compare any pause with the target interval.
2. A protocol-level response matrix for the same plan: `Unavailable`, silent timeout, and properly correlated `Busy`. Observe whether Busy keeps `active_suffix_sync` present and mining closed after 45 seconds.
3. Add a healthy peer that produces a stronger competing branch. Confirm whether the victim replaces the stalled plan and resumes mining, and how long this takes.

If the state-machine reading is confirmed, a defensive change is to bound cumulative no-progress time or repeated Busy replies per exact provider and plan, independently of whether the source remains connected. Retirement should resume mining on the last committed valid tip while continuing low-rate discovery for the selected header. Authenticated object progress and local verification need separate protection so a slow but real provider is not mistaken for a liar. This area deserves a focused regression test of the readiness transition and failover, not just a unit test of the fetcher's counters.
