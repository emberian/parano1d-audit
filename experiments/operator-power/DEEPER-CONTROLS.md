# Service influence beyond explicit protocol authority

Source review, 2026-11-15. Target: `52938433a30b185ab007afaa15166a632cf2e82e`. This follows the [control-surface map](OPERATOR-ATTACKS.md) and [bootstrap review](REPORT.md). It used no public P2P connection or exploit harness. “Service controller” denotes whoever controls a particular endpoint, credential, or release channel; the source does not identify that person.

## A single peer can govern a miner's readiness lease

Normal mining requires one healthy peer failure domain (`noid_node/src/main.rs:533,574-609`). A connected, network-profile-compatible peer can confirm the miner's **exact locally committed tip** by announcing its header at the same height and hash (`main.rs:10011-10067`), or by returning a matching header inventory (`main.rs:11218-11237`). `confirm_tip` renews both the peer-health lease and frontier authorization (`main.rs:725-751`); `MiningReadiness::snapshot` requires those leases, initial sync completion, and no unresolved better header before nonce search (`noid_node/src/networking/mining_readiness.rs:187-230`). The confirmation expires after 45 seconds unless renewed; the event loop expires it and probes peers again (`main.rs:554,14573,15090-15128`).

This is a **conditional availability and freshness coupling**, not a special seed permission. If a miner has only one usable peer and that peer is a default seed or a peer learned from it, the peer can sustain mining readiness by echoing the miner's existing tip, or let readiness expire by withholding matching responses. The echo proves agreement with the local hash, not knowledge of the best public tip. A service that supplied a miner's only peer route could therefore keep that miner working on a valid but stale local branch while independent blocks remain unreachable, or stop its nonce search after the lease expires. The one-peer threshold makes this possible without control of several failure domains. It does **not** let the peer choose a payout address, authorize an invalid block, or make its branch canonical to independent nodes. It also does not show that any actual miner has only that route or that this has occurred.

The limiting checks matter. Profile agreement authenticates the P2P identity and exact network parameters, but does not attest to a global chain view (`noid_p2p/src/network.rs:7080-7141`). `confirm_tip` only accepts the node's committed height/hash (`main.rs:725-737`); a different or stronger chain must pass native header checks and HeaderDAG selection. An unresolved better data plan closes the mining gate (`main.rs:14561-14575`; `mining_readiness.rs:207-230`). Independent reachable peers can announce and serve their own tips; the node rotates probe candidates and does not pin confirmation to a seed. This lead concerns a miner's **view under isolation**, not a demonstrated way to redirect the network's canonical history or block another wallet's deposit.

## How far seed influence persists

The four unpinned default DNS names are dialed in addition to configured seeds (`main.rs:2256-2304`). During initial sync, topology policy retains up to two bootstrap connections; once stable ordinary peers replace them, it releases the seed links (`noid_p2p/src/network.rs:506-527,5389-5434,5602-5615`). The node seeks an eight-neighbor ordinary topology and credits at most four unselected inbound peers toward it (`network.rs:495-506`). Kademlia responses can supply candidate peer IDs and addresses (`network.rs:6917-6982`), so the first reachable seeds can shape the next set of dial attempts. This is the concrete path by which initial endpoint control may continue past the first connection.

There are guards against a simple permanent bootstrap capture: ordinary candidates must pass public-address and diversity checks (`network.rs:5540-5590`); saved peers are recorded only after successful outbound transport (`network.rs:4833-4839,6815-6825`); profile-incompatible peers are closed (`network.rs:6650-6687,7105-7134`). A collection of independently reachable, compatible peers can still occupy topology slots if it satisfies those checks. The source alone does not establish how many independent peers a fresh public node would reach, or whether a controller of one DNS zone also controls those later peers. The stronger first-contact question is therefore **peer-route diversity after discovery**, not whether a seed name itself has protocol authority.

## What this establishes

The new concrete coupling is the **single-peer mining readiness lease**. It makes a miner's ability to continue searching depend on a recent exact-tip claim from at least one reachable peer, and that peer may be a seed during bootstrap. Under an eclipse, an echo of a stale but locally valid tip can maintain the lease; silence can expire it. It does not provide an administrative spend path or by itself give one holder a special exchange exit. Assessing practical reach would require observing actual miner peer diversity, block production, and exchange deposit behavior; none was measured here.
