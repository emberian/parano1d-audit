## Finding: the listing-settlement circuit is doubly dead — unwired AND profile-blocked (informational)

**Severity: Informational — latent staging fact, not a vulnerability. Preconditions: none; it is a property of the pinned commit.**

Two independent facts close the nft lane's residual:

1. **`bind_financial_listing_settlement` has no caller in the tree.** The only function that takes `FinancialListingSeedTrace` (`bind_financial_settlements`, `noid_recursive/src/acceptance/trace/native_assets/financial_kernel.rs:387-394`) names the parameter `_listing_seeds`, never invokes the binder, and its sole call site (`block_slots.rs:3207-3215`) passes `&[]`. The seed plumbing (`FinancialHeaderWindow::listing_seeds`) is built and discarded. This corrects the nft lane's phrasing that the circuit is "wired for operation code 71": the wiring terminates in an ignored parameter.
2. **The shipped opening profile cannot bind a purchase request at all.** `financial_opening_root_trace` builds its one-hot kind selector from `profile::kind_enabled`, which omits `NftPurchase`. A `bind_financial_slot` on an `NftPurchase` opening is unsatisfiable by construction (`pin_eq(selected, 1)` fails since the kind's selector is the zero constant) — demonstrated by execution. Under the shipped profile the settlement binder can only be satisfied with the op-71 header flag set to 0, i.e. it can prove no settlement, vacuously.

Because both gates hold, no second-satisfying-witness exposure exists *as shipped*: there is no witness at all for a live settlement. To answer the residual's actual question — is the circuit's constraint set sound for the settlement it describes? — the witness was built in the **intended live configuration**: verbatim copies of the three private helpers (`opening_root_trace`, `amount_from_fields`, `bind_slot`) with the single change that `NftPurchase` joins the opening schema. Copy fidelity is pinned by a control: for every kind the shipped profile already admits (`NftListing`, `NftItem`), the copy accepts and rejects byte-identically to production (honest openings satisfy, field-mutated openings fail, both binders agreeing).

Against that configuration:

- **The honest witness satisfies.** A full settlement round — one frozen listing input (queue commitment, registered height, phase, generation), three funded purchase-request inputs, the winner's item output, four cash payout outputs, the op-71 header with exact input/output counts and fee, the round seed (parent id + alloc counter) — built from the real native settlement path (`ListingBatch::register` → `ListingSettlement::calculate`) satisfies the real `bind_financial_listing_settlement` R1CS. This is the witness the nft lane judged too heavy to build.
- **Native-vs-recursive agreement holds on every executed rule.** The circuit's winner key is `funded_key || payer_root || payer_priority` in native big-endian digest order with `payer_priority` as the most-significant segment (traced through `digest_bits` + the MSB-last `less_than` in the char-2 field), exactly matching native `min_by_key((payer_priority, root.0, funded_request_key))`; the queue ordering (`request_rows` host sort by byte-swapped lanes = native `Digest` order) matches `committed_queue_root`'s strict sort; the fee split `q + (i < r)` runs over key-sorted rows exactly as native iterates `ListingBatch::register`'s sorted requests; the settlement window (`registered+1..=registered+3`), the ask floor, the item-recipient binding and the payout aggregation all mirror the native path. Verified by execution: the independently recomputed native winner is the circuit's winner.
- **Second-satisfying-witness hunt: none found.** Five adversarial variants of the same witness are all unsatisfiable: delivering the item to a non-winner's recipient; settling at the registration height (too early); settling at `registered+4` (too late, refund phase); a frozen listing whose queue commitment is off by one bit; any single cash payout off by one µNOID.

The residual risk that remains is the flip side of the finding: the day the profile flips and the binder is wired in, it enters service having never executed in CI against a populated witness — this lane's PoC is the first (and currently only) executed witness for it.

## Negative and control results

**Operation 80 — executed for the first time through the real State apply path** (all prior lanes drove `TradeBatch`/`SequencingPlan` only; the dex-games lane drove the sequencing engine, not `prepare_trade_batch` → `apply_prepared_trade_batch`):

- **Honest end-to-end execution on a launch curve** (mid-flight curve seeded as a parent carrier, two buys + one sell in one batch): parent slot consumed, market successor installed, every payout materialized at its charge amount (NOID payouts in the raw amount lane, token payouts zero there by design), µNOID conservation `inputs = payouts + successor + fee` exact, supply burns exactly the batch fee, state root changes, created/consumed opening sets match the claim tables.
- **Batch-internal ordering is fully re-derived, never caller-supplied.** `TradeBatch::new` re-sorts policies by `authorization_id`; `SequencingPlan::execute` re-sorts by the `funding_priority` digest (`H("TRORD_21", parent_id, asset, anchor.creation_id, anchor.slot_index)`). Verified: caller order scrambled → identical root, fills, charges, outputs; two anchors ground so that authorization order is decoupled from priority order still execute in priority order (state-apply level, mirroring the dex-games tx-level control). Funding order inside an intent is canonicalized too (strictly ascending slots).
- **All-or-nothing atomicity per admitted batch.** A batch containing one declinable fill (a `minimum_output` unreachable at that fill's execution position) is rejected wholesale — `Batch(Unfilled)` from `TradeExecution::prepare`, State unchanged (state-root equality against a fresh twin asserted). The dex-games lane's miner-side pre-filtering (drop unfilled intents and retry) is what keeps failed batches out of templates; the consensus layer itself refuses them. A hard policy error (expired policy) aborts identically (`batch.checked` flattens every sequencing error into `Batch(Sequence)` — documented here since the error variant is lossy).
- **The trade kernel cannot touch NFT state.** Listing and item openings are rejected as trade funding by `TradeIntent::validate_funding`; the parent type `MarketStart` has no listing variant, so a listing parent is unrepresentable by construction. The op-80 surface and the listing escrow are disjoint opening families — no cross-contamination path exists at this commit.
- **Wire round-trip agreement.** `NativeIntent::from_trade_execution` → `prepare_trade_batch_from_intent` re-derives the execution from the paged wire and agrees with the direct derivation on inputs, outputs, charges, fee and fill order (the production two-implementation check a verifying node performs).

**Listing races (live ops 64/65/66):**

- **Two buyers, one listing (sequential windows):** exactly one purchase applies; in both inclusion orders the loser's transition fails whole with the loser's cash untouched, the seller paid once, the item delivered to the included buyer with identity preserved. Determinism: at the State layer the first *applied* wins; at the template layer the canonical candidate sort (fee-descending, txid tie-break — and financial ops pay exactly the required fee, so effectively txid) fixes the order; at the mempool layer the second intent is rejected at admission (input-slot conflict), so a shipped miner never holds both.
- **Cancel racing buy:** both interleavings leave a consistent world — buy-then-cancel fails the cancel (listing slot consumed; no refund output minted), cancel-then-buy fails the buy (buyer's cash intact). No interleaving moves the item and preserves the payment, or keeps the item and burns the payment: the listing escrow is a single UTXO and exactly one transition consumes it.
- **Stale listing across a real fork/reorg** (real MDBX chain, real templates, real PoW, `apply_reorg_mdbx_with_applier`): listing created on fork A; on competing fork B the seller transferred the item onward; B wins the reorg (two blocks, strictly more work). The reorg removes the fork-A listing entirely (its slot is EMPTY afterwards — nothing carries the stale listing forward), the attacker's transfer survives, and an instant-buy aimed at the fork-A listing coordinates is rejected at admission with `financial block: Read` (the `NativeParentRef` state-read check against the reorged parent). The marketplace seam over the storage layer's rollback is closed by the same UTXO binding that closes the sequential races.
- **Same-block double inclusion:** two purchase intents for one listing in one template — each alone produces a valid block; both together abort the template build (`StateApplyError("native block: SlotConflict")`). No partial block, no double spend; the miner loses the build, not the chain. (Direct candidate injection is operator-local; the mempool's slot-conflict admission already prevents the pair from coexisting in a shipped miner's queue.)
- **Failed buys cost the submitter nothing at admission:** a stale/attacker purchase fails at `check_financial_owner` against the parent view before any fee is due; failed transitions never enter blocks, so there is no failed-but-charged inclusion. The vendor-lock variant of the brief (a listing crafted to waste a buyer's inclusion cost) has no surface: `min-out`/fee configurations are buyer-side parameters of the *buy*, and the listing itself cannot force a charged failure.

**Wash-trading economics (measured, floor state geometry):**

- Self-list + self-buy round trip: **16 400 µNOID per cycle** (list fee 6 600 + buy fee 9 800), of which 2 500 burned and 13 900 miner-claimable. The 100 000 µNOID escrow credit is returned on purchase and the ask round-trips to the seller, so the marginal wash cost is exactly the two fees.
- A miner washing their own listing recaptures the claimable 13 900 (paying themselves), netting 2 500 µNOID/cycle at the floor geometry — but the fee schedule is state-pressure-indexed (the nft lane measured the 8× pressure multiplier), so sustained wash volume raises its own cost per cycle.
- There is no listing/creation fee beyond the spend-lane fee: listing spam costs the listing fee + one state slot + 100 000 µNOID escrow per live listing (escrow recoverable on cancel minus the cancel fee); uncancelled listings persist as ordinary UTXO state, feeding the creation-spam lane's measurement program rather than adding a new mechanism here.

## Guardrail table

| Race | Deciding mechanism | Deterministic? |
|---|---|---|
| Two instant-buys, one listing (across blocks) | Listing escrow is one UTXO; first *applied* transition consumes it (`Phase`/input check rejects the second) | Yes, once inclusion is fixed |
| Order of the two in one template | Canonical candidate sort: fee-descending, txid tie-break; financial fees are exactly the required minimum, so txid decides | Yes (miner policy outside the shipped assembler, but the sort is canonical) |
| Both buys in one block | Second group fails State application (`SlotConflict`) → whole template build aborts; block invalid if hand-forced | Yes |
| Cancel vs buy in one window | Same single-UTXO consumption; the late transition fails whole | Yes |
| Listing on fork A vs item transfer on fork B | Reorg rolls back the losing fork's UTXO set; the stale listing ceases to exist; stale buy fails the parent-ref State read (`Read`) | Yes |
| Trade order inside one op-80 batch | Re-derived: `authorization_id` sort (encoding) then `funding_priority` digest (execution); caller order irrelevant | Yes (digest re-salted per parent block) |
| One declined fill in an op-80 batch | Whole batch rejected (`Unfilled`); miner pre-filters; State untouched | Yes |
| Round-settlement winner (op 71, currently gated) | `min(payer_priority, request root, funded key)`; circuit enforces the same key in the same byte order | Yes |

## Assurance limits

- The settlement-circuit witness uses verbatim copies of three private helpers with one line changed (`NftPurchase` admitted to the opening schema); every other constraint is production code. The copy's fidelity is asserted for the kinds the shipped profile admits, not for `NftPurchase` itself (there is no production reference to compare against at this commit). The finding "no second satisfying witness" is relative to the five adversarial variants tested, not an exhaustive proof of constraint soundness (the constraint-systems lane owns the general compiler audit).
- The claim that the full production-configured binder is vacuously satisfiable with the op-71 flag at 0 is code-read (every conditional constraint vanishes; the all-dead cash-payout rows satisfy `bind_financial_cash_payouts`); only the flag-independent opening-level block (`NftPurchase` selector unsat) was executed.
- **The recursive trade kernel (`bind_trade_kernel`, op 80's circuit) was not witnessed.** The brief's native-vs-recursive item for executed trades is covered only by the two-derivation native agreement (`TradeExecution::new` vs `from_claims`/`from_intent`, which is what block verification re-derives). The trade kernel takes the same directly-constructible trace types as the settlement binder plus real batches as host hints, but drives ~3 100 lines of sub-binders (market projection over the action table, flat funding rows, batch roots, global execution, payout and owner-authorization statements) whose exact trace shapes are undocumented; building it is the named successor task for this surface. Its sequencing-ordering semantics (priority digest, side preference, decline handling) are however shared with the native engine this lane executed, and the dex-games lane PoC-verified those semantics at the tx layer.
- The op-80 fixture seeds the launch-curve parent synthetically in `ChainState` (the launch creation path is the dex lanes' surface); everything downstream of the parent claim — preflight, fee quotes, sequencing, materialization, apply — is production code. The launch state itself was not created through op 48 in this lane.
- The reorg PoC stubs the recursive HistoryStep terminal (storage-reorg lane's posture); all native header/PoW/anchor/state-root/financial checks are real. The chain is short (tip height 33), single miner, genesis-floor difficulty; multi-epoch financial windows and network-scale blocks were not exercised.
- The two-buyer and cancel-vs-buy races were driven at the State-apply layer (and the template layer for double inclusion); the mempool admission layer was read, not driven (no mempool server was started).
- Wash economics are measured at the floor state geometry (lowest fee schedule); the pressure-multiplier response is taken from the nft lane's measurements, not re-measured here.
- No upstream source was edited and no fix was applied.
